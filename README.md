# Replenishment Decision Quality: A Simulation-Based Evaluation and Monitoring Framework for ML-Driven Retail Stock Distribution

## Project Description

Retail chains move products from central warehouses to individual stores every
day. These distribution decisions are increasingly made by machine-learning-
driven replenishment systems, which combine sales forecasts with business rules
such as minimum stock levels, pack sizes, and store priorities.

Although such systems produce decisions daily, the *quality* of those decisions
is rarely measured in a structured way. Forecasts are seldom compared with
actual sales systematically, and when the shipped quantity differs from the
forecast, it is difficult to tell whether the cause was a model error, a
warehouse stock shortage, or a business-rule constraint. Evaluating such a
system on real production data is also often impossible, because retail data
is commercially confidential.

This project removes both barriers with a simulation-based design. It builds a
**synthetic retail world** - a fictional footwear retailer with stores,
products, a warehouse, and two years of daily sales - generated by a
calibrated data generator, so no real records are ever used. Inside this
world, a forecasting engine and a rule-based replenishment simulator produce
decisions every day, and an evaluation framework measures their quality
against a known ground truth. The whole pipeline is reproducible by anyone.

## Objective

Develop a framework that can:

1. **Generate a realistic synthetic retail world** - stores, products,
   warehouse stock, sales history, and a hidden future with known true demand
   (seasonality, store and product profiles calibrated from real retail
   patterns, but fully artificial data).
2. **Simulate ML-driven replenishment** - produce sales forecasts from the
   synthetic history and turn them into distribution decisions through
   business rules (minimum stock, pack size, warehouse availability).
3. **Measure decision quality** - compute forecast-accuracy metrics (WAPE,
   MAPE, bias) and classify forecast-vs-shipped deviations by cause (model
   error, stock constraint, rule constraint, other).
4. **Visualize** - present results by store, product category, and season in
   an interactive dashboard.

## Target Users

- Retail analytics and planning teams who need to know where a replenishment
  system performs well or poorly.
- Category managers and demand planners who monitor stock health for their
  product ranges.
- ML engineers who maintain forecasting models and need systematic feedback.

## Planned Features

- FR-01: Parametric, seed-based synthetic retail world generation
- FR-02: Store-product level demand forecasts (statistical baseline + ML model)
- FR-03: Rule-based replenishment simulation (minimum stock, pack size, warehouse availability)
- FR-04: Forecast-accuracy metrics (WAPE, MAPE, bias) aggregated by store, category, and season
- FR-05: Deviation-cause classification (model error / stock constraint / rule constraint / other)
- FR-06: Interactive dashboard with store, category, and date filters

## Scope

The first version includes the five pipeline components (synthetic world
generator, forecast engine, replenishment simulator, evaluation framework,
dashboard) and automated tests. Excluded: any real or confidential data,
model retraining, streaming analysis, customer-level analysis, and price
optimization. The full specification with non-functional requirements, user
stories, and milestones is in `docs/requirements.md`; planned work is
tracked in
[GitHub Issues](https://github.com/KaganxSahin/replenishment-decision-quality/issues).

## Planned Technologies

- Python 3.12
- NumPy / pandas (data processing and synthetic data generation)
- LightGBM and statsmodels (forecasting engine)
- Streamlit (interactive dashboard)
- pytest (testing)
- Git & GitHub (version control)

An optional SQL connector for future real-data deployment is planned as an
extension; the graduation project itself runs entirely on the built-in
synthetic generator. Technologies may evolve during the project.
