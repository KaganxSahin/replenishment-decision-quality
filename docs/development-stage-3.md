# Development Process - Stage 3: Replenishment and Initial Evaluation

| Field | Record |
|---|---|
| Date | 17 November 2026 |
| Objective | Connect the forecaster to a synthetic replenishment simulation and provide initial metrics, cause summaries, and an interactive dashboard. |
| Requirements | FR-04, FR-05, FR-06, and FR-07 (dashboard priority is Should); supports the end-to-end data-independence objective in NFR-04. |
| Implemented functionality | `src/rdq/simulator.py` applies minimum-stock and pack-size rules, allocates finite warehouse stock deterministically across store requests, carries store inventory across days, and records shipped quantity, sales, lost sales, overstock, and stock-out indicators. `src/rdq/evaluation.py` calculates WAPE, MAPE, and bias overall and by store, product category, season, and store-product pair. `src/rdq/pipeline.py` orchestrates generator → emulator → simulator → evaluator. `src/rdq/dashboard.py` provides configurable synthetic runs, store/category/date filters, metrics, charts, and simulation records. |
| Data flow and output | `run_pipeline` returns generated world tables, forecasts, a combined simulator decisions/outcomes DataFrame, and evaluation metrics/cause summaries. Future true demand is provided to the simulator for the controlled simulation but is not given to the forecaster. The CLI withholds true-demand samples; generated data remains in memory. |
| Cause-label boundary | The simulator assigns a heuristic label with priority stock constraint → rule constraint → model error → other. The evaluator summarizes these labels; it does not independently infer causal attribution. A label is not proof of an exclusive cause, especially when constraints overlap. Dedicated known-answer classification tests are not yet implemented. |
| Technical decisions and limitations | Decisions and outcomes are returned in a combined table rather than separate artifacts. Warehouse stock is one opening snapshot and depletes during the horizon; no replenishment inflows, lead times, or store priorities are modeled. The simulator and metrics are prototype logic for generated data, not production monitoring. |
| Problems and solutions | Streamlit `AppTest` initially exposed package-relative import failures; dashboard imports were changed to absolute `src.rdq` paths. Streamlit 1.67 dataframe calls were aligned with its supported width API. A rule-check edge case that mislabeled a pack-size reduction was narrowed to actual minimum-stock or pack-size restrictions. Final dashboard, simulator, and full-suite tests passed. |
| Verification | 27 standard-library `unittest` tests passed, including metric hand-calculation checks, simulator rules and inventory carry, pipeline repeatability, and dashboard render/filter smoke coverage. Two default seed-42 CLI outputs compared byte-for-byte with no differences. These checks do not replace Week 6 known-answer, performance, and broader validation. See [tests](../evidence/week-05/tests.txt), [first run](../evidence/week-05/pipeline-run.txt), [repeat run](../evidence/week-05/pipeline-run-repeat.txt), and [comparison](../evidence/week-05/repeatability-check.txt). |
